# Генератор ценовне површине

Како `generator.js` прави месечне цене стана по m² на мрежи над Србијом —
која математика стоји иза тога, шта се мења да излаз буде другачији, и где
су границе.

> **СИНТЕТИЧКИ ПОДАЦИ.** Ништа у овом ланцу не долази из стварног промета
> непокретности. Бројеви су измишљени тако да личе на стварне — то је
> довољно да се приказ испроба, а недовољно за било какву процену
> вредности, поређење подручја или илустрацију уз тврдњу о стварном стању
> тржишта.

---

## Шта ради

Једна функција, два улаза, један излаз: за задати корак мреже у километрима
прави тачке унутар границе Србије, па за сваку тачку и сваки од 96 месеци
(01/2019 – 12/2026) рачуна цену у еврима по m².

```
                               извод из РГЗ-а
                                      │
                                      ▼
                            pretvori.js
                                      │
                                      ▼
generator.js ──→ generisi.js ──→ podaci_3km/ ──→ napravi-hex.js ──→ hexagon-layer.html
     │                           tacke.csv           --podaci
     │                           cene.bin
     │                           meta.json
     │
     └──→ za-kepler.js ──→ kepler_3km.csv ──→ kepler.gl
```

Исти `generator.js` ради и у Node-у и у прегледачу. Без `--podaci`,
`hexagon-layer.html` не носи никакве податке — рачуна их сам, у прегледачу,
истим кодом и истим семеном. Зато један фајл ради било где. Детаљи о
паковању су у [`../prototip/README.md`](../prototip/README.md).

| | на кораку 3 km |
|---|---|
| тачака | 9.832 — оквир 107 × 173, унутар границе остане 53,1 % |
| месеци | 96 — 01/2019 до 12/2026 |
| вредности у низу | 943.872 — на кораку 0,5 km је 34 милиона, отуд бинарни формат |

## Шест слојева математике

Цена у ћелији `k` у месецу `t` настаје као производ четири чиниоца, а сваки
од њих има свој поступак. Редослед је стваран: сваки слој користи излаз
претходног.

```
cena[k][t] = baza[k] · indeks[k][t] · sezona(t) · (1 + šum[k][t])
             └ слој 3  └ слој 4+5     └ слој 5         └ слој 5
```

### 1. Пројекција — из степени у километре

`lonLatUKm()` · `KM_PO_STEPENU_LON = 80,077`

Еквидистантна цилиндрична пројекција око `LAT0 = 44°`. Постоји из једног
разлога: степен географске ширине је 111 km, а степен дужине на 44° је само
80 km. Мрежа у степенима дала би издужене правоугаонике; мрежа у
километрима даје квадрате. Све даље — растојања до градова, корак шума,
корак мреже — мери се у километрима.

Изобличење преко Србије је око 3,5 %. Оно **више не улази у размак ћелија** —
решетка се слаже по паралелама, види слој 2 — али остаје у растојањима до
градова и у кораку шума, где је за синтетику прихватљиво. За стварни посао
иде UTM 34N.

### 2. Мрежа — шестоугаона решетка, па одсецање границом

`napraviMrezu()` · `uPoligonu()`

Решетка је **шестоугаона**, не квадратна: приказ црта једну ћелију по тачки,
а шестоуглови попуњавају раван без рупа само ако су средишта тако сложена.
`korakKm` и даље значи страну квадрата исте површине, из ње се рачуна
полупречник `R = korakKm / √(3√3/2)`, а из њега размаци:

```
размак врста   1,5 · R      по географској ширини
размак колона  √3 · R       по географској дужини
свака друга врста померена за пола колоне
```

Шестоугао стоји **теменом нагоре**. То није естетика него последица
пројекције: степен дужине није свуда исто дугачак — 80,1 km на 44. паралели,
77,1 на 46,2 и 82,9 на 41,9. Ако свака врста лежи на једној паралели, размак
колона у степенима може да се рачуна баш за ту паралелу, па растојање на тлу
свуда остаје `√3·R`. Да шестоугао стоји теменом настрану, колоне би биле
усправне и морале би да држе исти размак кроз све паралеле — а то не може.

> Ранија верзија је узимала једну вредност за целу земљу, ону на 44.
> паралели. Ћелије су се зато на северу преклапале за 3,7 %, а на југу
> остављале фугу од 3,5 %. Види се при попуњености 1,00.

Свако средиште пролази кроз **ray-casting тест** (познат и као *even–odd
rule*, PNPOLY): повуче се полуправа од тачке удесно и броје се пресеци са
страницама полигона. Непаран број пресека значи „унутра". Тридесет редова
кода, без иједне библиотеке.

Број тачака расте са **квадратом** густине: преполовљен корак даје четири
пута више тачака.

### 3. Базна цена — где је скупо (простор)

`osnovnaCena()` · `GRADOVI` · `napraviSum(seme, 4, 90)`

Два потпуно различита извора се мешају:

```js
// а) градски утицај — збир експоненцијалних језгара
gradSkor = Σ  težina · e^(−d / domet)
           градови

// б) текстура терена — вишеоктавни value noise
sum(x, y) = Σ  0,5ᵒ · bilinearno(решетка при кораку 90/2ᵒ km)
            o=0..3

// в) мешање, нормализација и гама
v    = 0,68 · min(gradSkor, 1,35)/1,35  +  0,32 · sum(x, y)
t    = (v − vmin) / (vmax − vmin)
cena = min + (max − min) · t^1,45
```

**(а) Градови** су 20 записа облика `[ime, lon, lat, težina, domet]`. Сваки
град је изотропно експоненцијално опадање — на растојању једнаком домету
утицај падне на 37 % (1/e). Утицаји се сабирају, па се два блиска града
појачавају.

**(б) Шум** је *value noise*, не Perlin: вредност у чвору решетке се не
интерполира из градијента него је сама случајан број. Између чворова иде
билинеарна интерполација са `smoothstep` ублажавањем `3t² − 2t³`, да прелази
не буду угласти. Четири октаве са амплитудом која се преполовљује (`fBm`)
дају крупне облике са ситнијим детаљем на њима.

**(в) Гама 1,45** је важна и лако се превиди: она гура већину ћелија ка
јефтином крају. Без ње би расподела била равномерна; са њом је десно
закошена — мало скупих зона, много јефтиних, као у стварности.

### 4. Фактор раста — где расте брже (простор)

`faktorRasta()` · `napraviSum(seme+991, 3, 120)`

Други, потпуно независан шум — три октаве, крупнија основна ћелија од
120 km — пресликан у множилац националног раста:

```js
rast[k] = 0,45 + 1,15 · sum(x, y)   // номинално 0,45 .. 1,60
                                    // стварно  0,61 .. 1,43 на 3 km
```

Ово је намерни избор, а не случајност: **мапа раста не изгледа као мапа
нивоа цена.** Скупо место може да стагнира, јефтино да полети. Да су
везани, бивaријантни приказ „ниво × раст" не би имао шта да покаже.

### 5. Време — сложени раст, сезона, корелисани шум

`napraviSeriju().sledeciMesec()` · `GODISNJI_RAST`

Три независна временска чиниоца:

```js
// тренд — геометријски, не линеарни
mesečna    = (1 + godišnjaStopa)^(1/12) − 1
indeks[k] *= 1 + mesečna · rast[k]              // акумулира се

// сезона — таласа око тренда, не акумулира се
sezona(m)  = 1 + 0,008 · sin(2π(m − 3)/12)      // ±0,8 %, врх у јуну

// шум — AR(1), аутoрегресивни процес првог реда
šum[k]     = 0,6 · šum[k] + 0,4 · N(0,1) · 0,006
```

**Зашто `(1+r)^(1/12)`, а не `r/12`:** да дванаест месеци помножено дају
тачно годишњу стопу. Линеарна подела би због сложеног камаћења премашила
циљ.

**Зашто AR(1), а не бели шум:** коефицијент 0,6 значи да сваки месец памти
60 % прошломесечног одступања. Без тога би цена скакала горе-доле сваки
месец и анимација би треперила; са њим одступања трају по неколико месеци,
као мали циклуси.

**Националне стопе** су закуцане по години: 5 % (2019), 3 % (2020), 9 %,
14 % (2022 — врх), 10,5 %, 6 %, 4,5 %, 4 %. Кумулативно преко осам година
то је **× 1,71**, односно **+71 %** за ћелију са фактором раста 1,0.

### 6. Случајни бројеви — детерминистички, по координати

`mulberry32()` · `gauss()` · `vrednostResetke()`

Нигде се не користи `Math.random()`. Основа је **mulberry32**, генератор са
32-битним стањем, а нормална расподела се добија **Box–Muller**
трансформацијом из два униформна броја.

Кључни трик је у шуму: вредност у чвору решетке се не вуче из низа него се
**изводи из хеша саме координате**:

```js
v = mulberry32( (i*73856093) ^ (j*19349663) ^ seme )()
```

Зато не зависи од редоследа позива. Исто семе увек даје исти шум, на сваком
кораку мреже, у Node-у и у прегледачу. То је разлог што
`hexagon-layer.html` може да израчуна своје податке у прегледачу и добије
исто што и CLI.

## Калибрација скале — два режима

Ово је вероватно најмање очигледан део, а највише утиче на то како мапа
изгледа у јануару 2019.

Задатак је био: цене у опсегу 1000–3000 €/m². Али ако база заузме цео тај
опсег, раст преко осам година је однесе на 5570. Генератор то решава тако
што **уназад сабије базну скалу** за онолико колико ће раст да је подигне:

```
baznaMax = max / (maxIndeks · 1,03)   // 1,03 = резерва за сезону и шум
         = 3000 / (2,135 · 1,03)
         = 1364
```

| режим | базна скала 01/2019 | цене кроз цео низ | одсечено |
|---|---|---|---|
| `opseg` — подразумевано | 1000 – 1364 | 1000 – 2627 | 437 / 974.400 |
| `realno` | 1000 – 3000 | 1000 – 5570 | 54 / 974.400 |

**Последица коју треба знати:** у режиму `opseg` јануар 2019. изгледа
готово равно — распон од свега 36 % између најјефтиније и најскупље ћелије.
Контраст на мапи долази тек кроз време, кроз разлике у расту. Ако желите да
се већ први месец види разлика Београд–унутрашњост, треба вам
`--rezim realno`.

Цифра 2627 није грешка: горњи крај опсега се не дохвата јер ћелија са
највишом базном ценом није иста она са најбржим растом. Види
[налаз 2](#простор-за-исправку).

## Шта излази

Четири фајла по покретању. Формат је намерно такав да га и приказ и будућа
конверзија из РГЗ-а могу да користе непромењен.

| фајл | шта носи | 3 km | 0,5 km |
|---|---|---|---|
| `tacke.csv` | `id, lon, lat, bazna_cena, faktor_rasta` — геометрија и оба просторна слоја | 0,4 MB | 14,9 MB |
| `cene.bin` | `uint16` LE, месец-major: `[месец0: све тачке][месец1: …]` | 1,9 MB | 70,1 MB |
| `meta.json` | димензије, списак месеци, опсези, напомена о синтетици | 2 KB | 2 KB |
| `uzorak_long.csv` | првих ~5000 редова у long формату — само да се види шема | 124 KB | 124 KB |

**Зашто `uint16`, а не CSV:** цео низ у long CSV-у био би око 25 MB на 3 km,
а 900 MB на 0,5 km. Два бајта по вредности дају цео број 0–65.535 €/m², што
је за ову намену и више него довољно.

**Зашто месец-major:** приказ увек тражи „све тачке за један месец". Такав
распоред значи да је то један непрекидан блок меморије — `cene[t·n + k]` —
па клизач времена ради без иједног копирања.

## Шта се мења

Поређано од најбезбеднијег ка најдубљем. Све испод прве табеле је измена
једне константе у `generator.js` — нема структуре коју би требало
преправљати.

### Без дирања кода — аргументи командне линије

| аргумент | шта мења | опсег који има смисла |
|---|---|---|
| `--korak` | густина мреже у km | 3 → 9.832 тач. · 1,5 → 39.303 · 0,5 → 353.636 |
| `--rezim` | калибрација скале | `opseg` или `realno` |
| `--izlaz` | фолдер за резултат | било која путања |
| `--uzorak` | колико редова иде у long CSV | 5000 подразумевано |
| `--mesec-korak` | прореживање времена — само `za-kepler.js` | 3 = квартално, 12 = годишње |

```bash
node generisi.js --korak 1.5 --rezim realno --izlaz ./podaci_15km
```

```bash
node za-kepler.js --korak 3 --mesec-korak 3 --izlaz ./kepler_kvartalno.csv
```

### Облик мапе — где је скупо

| шта | где | сад | шта мења |
|---|---|---|---|
| `GRADOVI` | `generator.js` | 20 записа | **Најдиректнији алат.** Сваки ред је `[ime, lon, lat, težina, domet]`. Тежина је колико град подиже цену, домет у km колико се далеко осећа. Златибор и Копаоник су ту као „туристичка премија" — пример како се убаци нешто што није град. |
| `0.68` / `0.32` | `osnovnaCena()` | град vs. текстура | Више ка градовима → звездаста мапа, оштри врхови око центара, празно између. Више ка шуму → мрљаста мапа без препознатљиве структуре. Збир треба да остане 1,0. |
| `Math.pow(t, 1.45)` | `osnovnaCena()` | гама 1,45 | Колико су скупе зоне ретке. `1,0` = равномерна расподела, мапа делује равно. `2,0` = још мање скупих зона, оштрији контраст. Испод 1,0 се скупо шири и мапа се „упали". |
| `napraviSum(seme, 4, 90)` | `osnovnaCena()` | 4 октаве · 90 km | Крупноћа текстуре. `90` је основна ћелија у km — спустите на 30 за ситнију мрљу, дигните на 200 за две-три велике зоне преко целе земље. Број октава контролише колико ситног детаља седи на крупним облицима. |
| `seed` | `napraviSeriju()` | `20260826` | Други број даје потпуно другу мапу исте структуре — исти градови, иста статистика, другачији распоред текстуре. За варијанте и сценарије. Исто семе увек даје исти резултат, па је излаз поновљив. |

### Кретање кроз време

| шта | где | сад | шта мења |
|---|---|---|---|
| `GODISNJI_RAST` | `generator.js` | 0,03 .. 0,14 | Национални профил по годинама. **Овде улази стварни индекс** кад стигне — из РГЗ-овог регистра цена или НБС-овог индекса. Мењајте слободно; кумулативни максимум се рачуна из ових бројева, па се цео ланац сам прилагоди. |
| `GODINE` | `generator.js` | 2019 .. 2026 | Период. `BROJ_MESECI` се изводи из дужине овог низа, а клизач у приказу чита број месеци из података — ништа није закуцано на 96. Свака додата година мора да има свој ред у `GODISNJI_RAST`. |
| `0.45 + 1.15 · sum` | `faktorRasta()` | 0,45 .. 1,60 | Колико се раст просторно разликује. Сузите на `0,9 + 0,2·sum` и цела земља расте готово исто — мапа индекса постаје равна. Раширите за оштре контрасте између зона које лете и зона које стоје. |
| `0.6` / `0.006` | AR(1) у `sledeciMesec()` | меморија / јачина | Први број је колико месец памти прошли (0 = бели шум и треперење, 0,9 = спори таласи). Други је јачина одступања, око 0,6 % по кораку. Дигните га и серија постане немирна. |
| `0.008` | `sezona()` | ±0,8 % | Амплитуда сезонског таласа. Број `3` у `(mesec − 3)` помера врх — сад је у јуну. Не акумулира се, само таласа око тренда. |
| `min` / `max` | `napraviSeriju()` | 1000 / 3000 | Опсег цена у €/m². Ако ово мењате, погледајте и `CENA_MIN`/`CENA_MAX` и `IND_MIN`/`IND_MAX` у [`../prototip/hex-app.js`](../prototip/hex-app.js) — тамо су границе палете и висине, и не изводе се из података. |

### Замена целог дела

`GRANICA` у `generator.js` долази из **Natural Earth 1:10m Admin 0**, слојеви
`SRB` и `KOS`, упрошћена Douglas-Peucker-ом на 0,002° (око 220 m): 774 темена,
површина 88.363 km² према званичних 88.499 km².

Званична граница из ГеоСрбије упада директно на њено место: `napraviMrezu()`
прима границу као други аргумент, а `uPoligonu()` прима **један прстен или
низ прстенова** и враћа тачно ако је тачка у било ком. Вишеделни полигони
(енклаве, острва) раде без измене кода.

## Ограничења

Шта генератор не може, и где би резултат преварио некога ко не зна како је
настао.

- **Мрежа је потпуно попуњена.** Свака ћелија унутар границе има цену — и
  шума, и језеро, и њива. Стварни подаци имају рупе јер станова нема тамо
  где нема зграда. Клизач „обухват података" у приказу је замена за то, али
  генератор и даље прави пуну мрежу.
- **Месечни шокови нису просторно повезани.** AR(1) је независан по ћелији.
  У стварности суседне ћелије расту заједно; овде их држи заједно само
  глатко поље `rast[k]`, док је месечно одступање чисто локално. Види се
  као благо „светлуцање" суседних шестоуглова из месеца у месец.
- **Нема стварних структура.** Нема коридора аутопута, реке, границе
  општине, ковид-шока 2020. Раст је гладак брежуљкаст шум — леп, али без
  иједног објашњења иза себе.
- **Једна вредност по ћелији.** Нема типа непокретности, површине,
  спратности, старости. Све је „стан од 50 m²".
- **`sledeciMesec(t)` мора да се зове редом.** Држи акумулативно стање
  (`indeks`, `sumStanje`). Ако се затражи само месец 50, резултат је *тихо*
  погрешан — нема грешке, само погрешни бројеви. `za-kepler.js` то поштује:
  зове сваки месец па прескаче писање.
- **Пројекција није званични CRS.** За било шта што се пореди са стварним
  катастарским подацима иде UTM 34N (EPSG:32634), односно EPSG:8682 за
  српски референтни систем.
- **Граница није катастарски податак.** Natural Earth је картографски извор
  за ситну размеру. Одступа од званичне границе за око 0,15 % по површини, а
  локално и до неколико стотина метара — што је испод једне ћелије на кораку
  од 1,5 km, али није ништа за посао који се пореди са катастром. За то иде
  званична граница из ГеоСрбије.
- **`uint16` нема децимале.** Заокруживање на цео евро по m². За приказ
  неважно, за даљу обраду треба знати.

## Простор за исправку

Шест ствари нађених читањем кода. Ниједна не квари садашњи излаз, али свака
је клопка ако се нешто промени.

**1 · запис — формула за `baznaMax` се скраћује сама са собом.** Написано је
`o.min + (o.max / (maxIndeks * 1.03) - o.min)`. Алгебарски се `o.min` скрати
са `− o.min` и остане чисто `o.max / (maxIndeks · 1,03)`. Резултат је тачан
(1364,2), али запис наводи на то да доња граница улази у рачун — а не улази.
Скратити, да се следећи пут не чита погрешно.

**2 · излаз — горњих 12 % опсега се никад не достигне.** `maxIndeks` се
рачуна из *глобално* најбржег раста, а `baznaMax` из *глобално* највише
базе. То су различите ћелије, па је граница конзервативна: стварни максимум
у низу је 2627, а не 3000. Губи се горњи крај палете — најтоплија боја се
не појави нигде.

```js
// уместо глобалних максимума, максимум производа по ћелији:
let vrh = 0;
for (let k = 0; k < n; k++) vrh = Math.max(vrh, baza[k] * indeksKraj[k]);
skala = o.max / (vrh * 1.03);
```

**3 · тиха замка — кључ кеша у шуму подноси само позитивне координате.**
`const kljuc = i * 100000 + j` је јединствен само док су `i` и `j`
ненегативни и `j < 100000`. Са садашњом пројекцијом (x ≈ 1509–1840 km,
y ≈ 4652–5132 km) и до 11 октава то увек важи. Али пројекција центрирана на
Београд дала би негативне координате, а преко 11 октава премашује 100.000 —
и у оба случаја се кључеви сударе, па шум *тихо* постане погрешан. Закрпа
је један знак: `i + ',' + j`.

**4 · поређење — иста тачка нема исту цену на два корака мреже.**
`osnovnaCena()` нормализује по `vmin`/`vmax` израчунатим из тачака које на
*том* кораку постоје. Гушћа мрежа ухвати оштрије врхове, границе се помере,
и иста географска тачка добије другу цену на 3 km него на 0,5 km. Ако
затреба да се две густине слажу — рецимо за проверу — фиксирати
`vmin`/`vmax` на константе уместо рачунати их из мреже.

**5 · закуцана граница — плафон градског утицаја не прати тежине.**
`Math.min(gradSkor, 1.35) / 1.35` — број 1,35 стоји сам. Ако се повећају
тежине у `GRADOVI`, све више ћелија удари у плафон и околина градова се
спљошти у равну плочу без градијента. Плафон треба да се изведе из тежина,
не да се држи независно.

**6 · меморија — један генератор случајних бројева по ћелији.**
`randPoCeliji` држи по једно затворење за сваку тачку — на кораку 0,5 km то
је 365.017 функција које живе кроз свих 96 месеци. Ради, али је то
најскупља ставка у меморији генератора и прво што ће пући ако се иде на
финију мрежу. Алтернатива је један `mulberry32` семенован из пара `(k, t)`
по позиву.

## `--promet` — рупичава табла, за пробу

```bash
node generisi.js --korak 3 --promet 120000 --izlaz ./podaci_3km_retko
```

Без ове опције је табла пуна, као и до сада. Са њом се одигра задати број
промета годишње, распоређен по близини градова, и цена **остаје само тамо где
је тог месеца било бар једне трансакције**. Остало се уписује као `0` —
договорена ознака за „нема податка“, иста коју приказ разуме.

На 3 km и 120.000 промета годишње испадне око **16 %** попуњених ћелија-месеци.
Сам распоред је измишљен као и цене; служи да се приказ и цео ланац испробају
на рупичавим подацима **пре** него што стигне прави извод.

`meta.json` тада носи и блок `pokrivenost` са уделом и напоменом да су
празнине симулиране.

## `pretvori.js` — из сировог извода у улаз за приказ

Карика која је недостајала. `napravi-hex.js --podaci` очекује `tacke.csv`,
`cene.bin` и `meta.json`; генератор их прави из измишљених цена, а овај скрипт
из **стварних трансакција**.

```bash
node pretvori.js --ulaz promet.csv --korak 3 --izlaz ./podaci_rgz
```

Читање CSV-а и тражење ћелије долазе из `citaj.js`, истог кода који користи
`prebroj.js`. То није штедња него услов: извештај о реткости мора да описује
баш онај скуп ћелија који приказ црта, па их `prebroj.js --proveri` покрива обоје.

Цена по m² се узима из једне колоне (`--cena`), или се рачуна из укупне цене и
површине (`--ukupno` + `--povrsina`). `--kurs 117.5` дели, ако извод пише у
динарима. `--samo VRSTA=stan` задржава само редове који се поклапају — стварни
извод носи и гараже и плацеве.

### Три одлуке које скрипт чини изричитим

Досад су биле прећутне; сада су прекидачи и уписују се у `meta.json`.

**`--sazmi`** (подразумевано `medijana`) — како се више трансакција своди на
једну цену ћелије. Медијана, јер је расподела десно закошена и просек би вукла
једна скупа продаја.

**`--najmanje N`** (подразумевано 1) — колико трансакција треба да ћелија-месец
уопште важи. Ово је најважнији прекидач, и ево зашто. Измерено на пробном
узорку од 480.000 трансакција, поређењем са правом површином из које су
извучене:

| трансакција | ћелија-месеци | медијана грешке | 90. перцентил |
|---|---|---|---|
| 1 | 59.740 | **12,1 %** | 29,7 % |
| 2 | 15.535 | 8,5 % | 21,4 % |
| 3–5 | 13.848 | 7,2 % | 17,9 % |
| 6–10 | 7.020 | 5,2 % | 12,8 % |
| >10 | 8.985 | 3,1 % | 8,2 % |

Са прагом 1, **57 % обојене површине стоји на једној трансакцији** — а таква
ћелија изгледа исто као она са двадесет. Отуд и опсег цена испадне 566–3973 €/m²
тамо где је права површина 1000–2664.

**`--prozor N`** (подразумевано 1, без попуњавања) — дозвољава ћелији да позајми
последњих N месеци кад текући нема довољно. Прозор враћа покривеност коју праг
одузме:

| подешавање | попуњено | ћелија са податком | опсег цена |
|---|---|---|---|
| `--najmanje 1` | 11,1 % | 58,0 % | 566 – 3973 |
| `--najmanje 3` | 3,2 % | 12,0 % | 697 – 3120 |
| `--najmanje 3 --prozor 6` | 10,9 % | 27,5 % | 697 – 3120 |
| `--najmanje 3 --prozor 12` | **16,9 %** | 32,6 % | 697 – 3120 |

Праг 3 са прозором од 12 месеци даје **више** покривености него праг 1 без
прозора, уз много чистији опсег. Цена је кашњење: цена од прошлог лета приказује
се као овогодишња. `prebroj.js` унапред каже шта који прозор доноси.

Прозор се рачуна над **сировим трансакцијама**, не над већ сведеним ценама —
просек просека није просек.

### Шта скрипт не решава

Две трансакције у истој ћелији нису иста непокретност. Медијана то ублажава али
не раздваја: разлика између два месеца и даље мери и кретање цене и промену
структуре онога што се продало. За раздвајање треба хедонистички модел или
индекс поновљене продаје. Док се то не уради, висина на приказу је груба мера,
и то стоји у `meta.json` под `sazimanje.napomena`.

### Проба без стварног извода

```bash
node prebroj.js --primer --godisnje 60000 --korak 3 --pisi uzorak.csv
```

Пише синтетичке трансакције са ценама извученим из праве површине, уз
логнормално расипање од 18 % — колико се појединачни станови разликују по
површини, спрату, старости и стању. Отуд и цела невоља са поређењем месеци.

## `prebroj.js` — колико је стварни извод редак

Пре него што се бира корак мреже, треба измерити колико података уопште има.
Генератор прави **потпуну** таблу — свака ћелија има цену у сваком месецу — а
промет то својство нема ни приближно.

```bash
node prebroj.js --ulaz transakcije.csv --korak 3,1.5 --prozor 1,3,6,12
```

За сваки понуђени корак исписује колико се табле заиста попуни, са померањем
прозора и без њега, плус концентрацију промета и расподелу броја трансакција
по непразном ћелија-месецу. Колоне се погађају из заглавља (`--lon --lat
--datum --cena` ако не). Раздвајач се одређује из заглавља, па наши изводи —
тачказапета уз децималну запету — пролазе без подешавања.

Праг за пуну таблу следи из саме мреже: на 3 km треба око **118.000** промета
годишње да свака ћелија добије бар једну трансакцију месечно, на 1,5 km око
**472.000**. Двоструко гушћа мрежа тражи четири пута више промета.

```bash
node prebroj.js --primer --godisnje 120000
```

Прави синтетички узорак — **не податке о промету** — само да се види како
извештај изгледа пре него што стигне прави извод.

```bash
node prebroj.js --proveri --korak 3,1.5,0.5
```

Проверава тражење ћелије: насумичне тачке се доделе и брзим путем (инверзија
решетке) и грубом силом, па се резултати упореде. То је једино место где
скрипт може да буде **тихо** погрешан, па ово треба покренути после сваке
измене геометрије у `generator.js`.

> Скрипт само **броји**. Не рачуна индекс и не пореди цене кроз време: две
> трансакције у истој ћелији нису иста непокретност, па њихова разлика мери и
> кретање цене и промену структуре онога што се продало. Раздвајање тражи
> хедонистички модел или индекс поновљене продаје.

## Кад стигне стварни извод

Ово је већ предвиђено у ланцу и не тражи преправку приказа.

Извод из РГЗ-а се **не чита нигде у овом коду**. Доведе се једном скриптом
за конверзију у иста три фајла која `generisi.js` већ пише — `tacke.csv`,
`cene.bin`, `meta.json` — а цео остатак ланца остаје непромењен. То је и
разлог што је формат такав какав јесте.

Тада се улога генератора мења: престаје да буде извор података и остаје као
*резерва* (фајл без уграђених података и даље ради свуда) и као алат за
попуњавање празнина тамо где стварног промета нема.

Напомена из `meta.json` се исписује у плочи приказа, па фајл никад не тврди
нешто друго него што заиста носи. Кад уђу стварни подаци, ту напомену треба
променити — иначе ће страница и даље писати да су подаци синтетички.
